BLACK POPUP — WHAT IS KNOWN
The Rails listing calls Kodi's native context menu on long press. Its former
buttons are Move, Remove and Manage. The standard select dialogs are called
only after choosing an action. The screenshot is consistent with a native
context panel. Official Kodi Omega source clones button 1000 into grouplist
996, adjusts background 999 from the grouplist height, and positions the
popup using the background's dimensions. Infinity .215 unified XML nests
that template and auto-height list in percentage-sized groups, making native
button sizing/background anchoring dependent on that nested geometry.
This is a confirmed source-level integration hazard. The exact on-device
failure path (geometry versus theme/resource fallback) cannot be conclusively
proved from a screenshot without a device render/log capture.

RC3 replaces the Rails presentation path, while preserving unrelated native
context controls. Home focus hooks record only the rail container. The native
context window's onload routes only a selected Rails item to the helper;
the helper captures its section/key, closes the native popup and opens the
owned DialogInfinityRails.xml. Only native long-press/context events reach
that route; focus, startup, taps and swipes do not open it. Actual native
onload-to-Python handoff must still be verified on the Fold.

THEMES / GEOMETRY
New Rails-only color variables read the current SystemTheme/native theme,
with OLED priority. No snapshot color cache or forced skin reload is used.
Opening/closing fades are 180/140 ms and honor OptionalMotionAllowed=false.
Geometry uses native published APP-WINDOW dp bounds and actual Kodi window
coordinates, matching the existing approved compact-preview transform.
Very short windows page actions; tiny windows scale the entire card uniformly.
Without native dp facts, geometry uses an explicitly approximate fallback.
A 200 ms bounds check exists only while this foreground modal is open. It
closes the menu on resize, an incomplete native bounds publication, or abort.
It never refreshes artwork/widgets and ends on dismissal. No background
service, startup worker, ongoing add-on polling or network call exists.

PERFORMANCE / LIMITATIONS
Only the affected rail receives a revision change. No full-home refresh,
skin reload, player command, or notification loop runs on add/remove/move.
Duplicate adds do not issue another refresh. Existing native scrolling is
retained. Kodi's list provider preserves the selected path, or the nearest
remaining index on removal, as its update code specifies. No new bespoke
neighbor-card animation is implemented: smoothness/focus/flicker depend on
the native provider and must be assessed on the device.

The host benchmark measured atomic state operations only. It does not measure
Fold GPU frame pacing, actual menu/input latency, artwork decoding, process
RSS, or long-session Kodi stability. See host-performance.json. Simulated
open/close cycles verify observer teardown, not device memory behavior.
