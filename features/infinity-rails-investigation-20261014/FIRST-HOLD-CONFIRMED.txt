CONFIRMED FAILURE
Installed profile and masterprofile super_favourites_menu.xml map global touch
longpress and mouse rightclick to RunScript(.../captureLauncher.py). The captured
maps contain no Home override for this hold. captureLauncher.py runs the installed
Super Favourites capture.py. Its menu creates the provider-owned WindowXMLDialog.
menus.py:76 fails in onInit: setPosition(..., newY), where newY = 360 - (height/2)
is a Python 3 float. Kodi requires an integer. Background/list heights are set
before the failing call; list population and focus initialization occur after it.
This explains the visible narrow black panel with no populated choices.

The installed map and source, observed window and contemporaneous exception
agree on this path. The observer does not record the raw Android action ID or
touch coordinates; the translation portion is source/keymap reconstruction.
AndroidTouch -> generic hold timer -> OnLongPress -> ACTION_TOUCH_LONGPRESS ->
InputManager touch translator -> SF RunScript -> launcher -> capture -> menus.
This captured route bypasses the native RightClick/container context callback.
No Rails management callback receipt is present. A dynamic selected identity is
available in Home, but that is not evidence of its receipt by Rails management.

REMAINING NATIVE BOUNDARY
The repository input implementation demonstrates two independent constraints:
1. GUIBaseContainer::OnMouseEvent (803-817) hit-tests RightClick, but skips OnClick
   if selection changes. The existing four compiled branch checks reproduce
   first-click selection only and second-click context dispatch. These are
   source-branch checks with adapters, not a physical reproduction of that gate.
2. InputManager::OnEvent, XBMC_TOUCH, sends a builtin action with actionString
   only, dropping touch coordinates. Mapping the hold directly to a Rails script
   can use current selection but cannot establish the actual held card. During
   gesture notification m_waitForScrollEnd suppresses hover selection.
Thus neither a simple RightClick restoration nor a direct RunScript remap is
verified to meet one-hold-on-the-actual-card across selection states. No such
candidate is released. Repository snapshots are not a byte verification of
installed libkodi.so, and this capture did not traverse the native RightClick gate.
