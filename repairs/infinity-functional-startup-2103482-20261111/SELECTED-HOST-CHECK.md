# Selected check, recorded before execution

Scope: native add-on admission and persistence bookkeeping only. No Android
application, provider, shutdown, restart, build or signing test is selected here.

Question: can repeated opaque-loader failure records alone deny a subsequent
independent script, or does denial require the separate admission gate?

Compile the retained production `ExecuteAsync` dispatch and admission methods,
`RunScript` built-in and persistence headers with controlled host peers from the
existing script-lifetime fixture. The native methods must match their retained
source hashes. Peers substitute the filesystem, handler/thread launch, add-on
lookup, logging and classification; **no Python add-on is executed**.

Run three independent, deadline-bounded host processes:

1. Record four repeated synthetic opaque-operation diagnostics 233 times for
   one existing writer. Verify bounded aggregation, unchanged open admission,
   and admission of an independent Program-script request. Preserve the failure
   record; do not clear it or claim durable shutdown. All four synthetic event
   names use the same opaque-writer classification; this does not exercise the
   actual audit hook or reproduce the original metadata-event classifications.
2. With identical records, close new startup admission using the real native
   method. Verify the independent request is refused and `RunScript` still
   returns zero without dispatching it.
3. Repeat the refusal check with the real hard-shutdown admission method.

The diagnostic fixture represents the ledger effect of failures, not Android
`dlopen`, the installed Core binary, CPU pressure, the GIL, actual checkpoint
failure, or the owner's incident. A host result can eliminate ledger poisoning
as a sufficient explanation under these conditions; it cannot establish which
condition existed on the Fold.

The previously identified CPython NULL/GIL cleanup contract is not selected for
execution in this check. A pinned interpreter would be required; a different
host Python version must not substitute for CPython 3.11.7.
