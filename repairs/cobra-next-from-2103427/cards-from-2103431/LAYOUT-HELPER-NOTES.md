# Cards layout helper — implementation checkpoint

`runtime/CobraCardsLayout.java` implements Cards-only presentation after personally viewing the exact private approved941×1672 PNG and original689×1536 JPEG; both SHA256 values match the approved brief. Reference images remain private and are not embedded or copied into repository/runtime assets. Pixel parity has not yet been established.

Integration APIs (public static):

- `beforeShell(Activity): void` before native shell/restyle: restore a prior Cards-owned hierarchy/styles when leaving Cards or replacing its guide shell. Repeated Cards restyles retain their owned state, avoiding unnecessary teardown.
- `layout(Activity,Object): void` after native visual geometry overrides: mutate the existing model's seven rect arrays in place and set Cards column count. Cards after-render refines checked physical layout parameters from the actual content pixel width and safe insets; this removes native integer-DP quantization at the approved941-pixel viewport. The original native model still governs its control visibility and routing. The prebuilt native `[[I` retains the same array identities.
- `afterRender(Activity): void` at native render and restyle returns, after `vtheme.tree`: apply Cards header, preview outline, native browser toolbar and GridView spacing/padding. Native configuration order is Layout→Render→Restyle, so the restyle-return hook is required too.
- `refreshPreview(Activity): void` LAST at each return of native `cobraRefreshVisualEffects`. The original native effect/ambient/status publication runs first. Cards uses its existing preview legacy TextView/StatusSlot for the approved LIVE chip only for an active, matching native live binding and native `cobraPlayerState` exactly `LIVE`. The original native pulse state is retained, while the chip replaces its healthy-LIVE presentation in Cards. Paused/buffering/error and non-Cards presentation restore native status.
- `refreshDetails(Activity): boolean` at the return of the original native details method. Native details/accessibility/header-count/brightness-description/ruler side effects execute first. The helper captures genuine native outputs before applying Cards formatting, then returns true only when actual Cards fields are ready. It does not replace or skip the native body.

Original native header/selector/source/search view instances, listeners, tags, glyph/caption metadata and menu ownership remain intact. Native icon buttons always draw a fallback even for an empty glyph, so Cards uses an opaque foreground drawn after their original icon, rather than changing their dispatch metadata. Original foreground/gravity and backgrounds are restored. API23+ supports ordinary-View foregrounds; API21/22 preserve native glyphs over the Cards panel (the accepted manifest minimum is21, target device API37). Native preview controls, click/longpress, TextureView, fit/aspect and player/session callbacks are untouched. The LIVE chip reuses the existing status label and direct StatusSlot hierarchy; no interactive overlay is inserted. Original label compound drawables/padding, alpha, style and container layout are captured. The native PiP avoidance routine receives the actual moved StatusSlot position through an owned layout listener, removed on restoration. Where native inline controls are visible, the chip clears their row rather than covering its hitboxes. Native live ownership uses existing `binding.vitals.live` (initialized by native channel validation) instead of rescanning the full channel inventory every tick. Guide-program title/description are the original native outputs; one current/inspected programme lookup supplies temporal boundaries. Same-day end time drops only the native duplicate date; cross-day output retains both dates. No channel, logo, programme, count or target-content name is hardcoded.

State creation waits for a real native mode layout, so the initial native restyle completes before snapshots/reparenting. Shared detail widgets/progress are then reparented into an owned FrameLayout. Cards displays the genuine nonempty native programme description despite the old190DP native threshold (the approved362-pixel panel is138DP at420dpi). The rendered progress level derives from the unchanged native ProgressBar value/max. Original child order/parents/layout-params, text styles/text, background/outline/clip/elevation, icon fields, ProgressBar drawable/tints and GridView spacing/columns are captured for restoration. Fresh native metadata is retained separately for restoration. The owned toolbar spacer is removed on restoration or header replacement. State is attached to the guide via a listener, while static owner references remain weak; no new service, timer, provider job or data write is introduced.

The only global geometry change is zero Cards stage padding. Its original padding is restored before non-Cards native styling. On detachment it is restored only if it still equals the helper's zero padding; native `clearStage` writes destination padding before detaching, and that newer padding is preserved. Details layout changes reflow only owned child geometry, without querying providers or changing data.

Repeated styling avoids replacing unchanged backgrounds/progress drawables/tints and avoids allocating unchanged layout parameters. Header count, eyebrow spans and temporal display strings are cached by their actual input values; time-zone, programme and count changes invalidate the relevant formatting. Native EPG/ticker publications remain responsible for freshness.
