# Cards visual correction checkpoint

Both documented production deviations from delivered 2103432 are corrected. The exact four selected host tests pass with the strict selection assertion retained. Tested source: `83c15217ee5209621145476160095d724d9fa22d`. This checkpoint contains production source and verification evidence; it is **not another APK**, release registration, signing decision or baseline lock. The corrections are not present in the previously delivered signed 2103432 APK.

The Cards header now uses its own weight-500 face, 42 px reference size and .03 em tracking. Other text weights remain unchanged. Card heights use the current native programme/status text and the maximum measured extent of the actual adapter row. Each holder retains bounded geometry inputs for its current row, rather than an inventory-wide cache. Metadata precedes measurement; changed content, adapter identity, row, width, font and paint metrics invalidate that holder's measurement. Both attached peers synchronize when one cell's height changes, without rebuilding or notifying the adapter.

Focused testing exposed an additional consequence of variable height: Android's `GridView.setupChild()` can clear a reused card's selected flag before laying it out, without rebinding. The existing card layout listener now reapplies **native `cobraModeSelected`** after that genuine resize, only after current Grid/adapter/position/channel and final-height validation. It does not derive selection from focus, add a worker or timer, replace the Grid listener, or modify shared/native code. The strict test first failed and now passes; no assertion was weakened.
