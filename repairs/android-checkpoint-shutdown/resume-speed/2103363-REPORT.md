## What changed

Only three functional scripts change, in matching Command Center 0.3.5.19 and installed 0.3.5.20 variants:

- `service.py:main/_publish_continue_state`: publish saved local Resume Hub counts/revision before skin maintenance and health/startup scans. Re-publish after maintenance so a skin reload cannot erase the restored properties. The widget revision and existing conditional property publisher remain unchanged. This does not move unrelated work to uncontrolled threads or skip health scans.
- `resume_hub.py:load_view/_view_data/_view_signature/poll_kodi_sync`: one bounded, read-only history snapshot per interpreter. File identity, inode, size, mtime and ctime for history, participant journal and engine identity invalidate the snapshot. Missing-file creation, atomic replacement, different profile, owner changes, journal mutations and unsafe file types cause fresh verified reads. Display callers receive private copies. Cache lock is never held while acquiring the writer gate. Idle polling can inspect an empty watched-update queue without repeatedly loading/hash-checking all history or entering a writer lease.
- `plugin.py:listing/_list_item/_target/_has_addon`: read shared source-memory and artwork tier once per listing, cache installed-provider checks only for that listing, and transform poster URLs once for poster/thumb. Routes, artwork choices, list size, skin properties, watched overlays and context actions remain the same. A new listing always rechecks providers/settings.

## Saving protections

Mutation reads (`load`), admitted writes (`save`), actual queued Kodi playcount RPC/readback (`flush_kodi_sync`) and all checkpoint drains remain fresh and verified. No cache is accepted as a saving receipt or checkpoint authorization. A failed RPC retains its durable queue entry. A newly queued operation detected during ordinary polling uses the original admitted path; the checkpoint always drains directly, including operations not yet noticed by an idle poll. Ordinary display may lag a concurrent atomic mutation until the next read; it cannot write stale display data back to history. Cache misses and unsafe types use the original participant checks and propagate failures.

The history schema, files, retention limits, watched/completion thresholds, saved positions, playcount semantics, local lists, settings and providers are unchanged. Trakt remains optional. Player, PiP, background playback, fold/rotation, skin and Choose Your Experience assets are not changed.
