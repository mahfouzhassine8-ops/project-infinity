# Observed Python save participation: candidate 2103338

This candidate connects unclassified Python invokers to the native checkpoint.
It does not grant an unconditional contract to every installed add-on or certify
physical Fold acceptance.

The observer is installed before add-on module initialization. Standard writable
Python file handles, SQLite connections and Kodi VFS writes have checked adapters.
Native audit events track filesystem mutations and reject unclassified external,
native extension, ctypes, mmap, DBM and metadata operations. Direct buffered opens
outside the checked adapter are refused as a shutdown proof.

After the player freezes, the coordinator notifies unclassified interpreters to
abort cooperatively. The invoker waits for child threads to retire. It does not
inject exceptions, join from the GUI, or destroy an interpreter owning a pending
transaction or failed buffered save. Only the owner's explicit commit or rollback
can resolve a transaction; shutdown never chooses one on its behalf.

Successful observer finalization is insufficient by itself. Native admission
counts must reconcile with actual interpreter destruction; all tracked persistent
files and namespace parents must sync successfully. Disk sync runs outside the
GUI thread. Late mutations invalidate the proof, including at final termination
authorization. The native status includes bounded pending writer identities,
writer/path counts, sync progress and errors without exporting file paths.

The Command Center/Resume Hub and Infinity compatibility service retain their
separate source-verified semantic checkpoint participants. Their final-position,
watched-state, clean-marker and shared JSON/RPC preservation gates remain required.
Binary PVR owners retain their existing explicit refusal.

Limitations: observed writes do not establish that an add-on ran every intended
semantic save. Add-on lifecycle audits and device evidence are still necessary.
Unclassified native/external persistence and unsupported storage durability block
termination. This includes diagnostic subprocesses until their process lifetime
and output ownership have explicit coverage. No unknown add-on is simply marked
safe because its script returned.

Local validation: seven real file/SQLite observer scenarios; six actual CPython
subinterpreter scenarios; 30 production coordinator scenarios; retained unknown
writer lifetime checks; 13 Command Center shutdown scenarios and 14 Resume Hub
preservation checks. Android/ARM64 compilation and physical device acceptance are
separate gates.
