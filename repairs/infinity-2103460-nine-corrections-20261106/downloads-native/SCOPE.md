# Downloads native candidate — exact signed2103460 foundation

The required only-Add-videos initial presentation cannot be implemented by labels or by deleting sources. A source created through the actual Downloads dialog is positive provenance; the dialog currently returns only a boolean. This candidate adds result-returning overloads to the existing dialog while retaining all old overload bodies, windows and permission rules. It stores selected source fingerprints in the existing Infinity per-profile skin settings owner, whose native dirty/admission/save protections are already present. No new database, cache, worker, source schema or persistence subsystem.

Native file allowlist: xbmc/video/windows/GUIWindowVideoNav.cpp and .h; xbmc/dialogs/GUIDialogMediaSource.cpp and .h. All preimages must match the exact compiled2103460 native source map. No shared Android/DEX, playback, provider, memory-retirement or shutdown source changes. Changes are dormant unless Android, active Infinity skin and explicit Downloads marker. Full ARM64 compile/link and exact source/binary preservation required before native packaging.

Selected checks before execution: old dialog method bodies reverse-byte preservation; actual result-returning functions against controlled UI/source-save transports; add/cancel/save-fail/edit, same-label/different-source, duplicate/reopened/profile membership, invalid preference schema, ordinary Files mode, folder-playback return and reset on other explicit navigation. No application shutdown tests. Existing skin setting persistence source is traced, not changed or bypassed. Failed writes remain failed and dirty; no success receipt is fabricated. Android GUI/file permissions remain pending a real target.

Safety ordering refined before verification: after user confirmation, the callback durably records the source fingerprint using the existing skin save API BEFORE the source is added/edited. A failed preference save prevents any source mutation. Earlier fingerprints are retained through edits, so an unsuccessful source save cannot hide the previous saved source. Orphan preferences grant no source access and create no source records. Source mutation then occurs inside the existing `xml_files` admission, checks the real source-save result and records failure without clearing any obligation. No admission or lock spans either user dialog or optional content assignment. This is necessary to avoid introducing a checkpoint/UI wait cycle.
