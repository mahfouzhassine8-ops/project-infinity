# TEST2 physical Fold: read-only maps durability failure

The protected baseline is commit `237dafd2`, native `d69e4d26`, and signed TEST2 APK SHA256 `172b1b4458cbe014c0f4ad242282e6dd97bf78d11cc8462db5badbf13f8fc807`. Run 38854391733 passed every one of the 308 Android host tests and actual emulator engine/whole-UID death, seven database integrity checks and saved-favourite reopening. Physical Fold acceptance failed and is authoritative for that device.

The 014425 ZIP confirms failure after 2410ms: 13 of 16 essential owners saved; native admission failed at `/proc/15237/maps`, databases and deferred dialog state remained pending, and authorization was never consumed. The ZIP does not record the original fd flags, inode or add-on caller. Do not invent those historical values or attribute the access to a particular add-on. Native ambient discovery has the exact `with open('/proc/self/maps', encoding='utf-8')` idiom, but that source observation alone does not identify the original physical caller.

The actual CPython 3.11.7 negative control identifies the registering operation: `_io.TextIOWrapper.close` enters `Call(TEXT_CLOSE)` and `BeginProtectedOperation` as `close`, with the real descriptor target `/proc/<pid>/maps`. Its nested native `flush` also registers the input. Explicit `TextIOWrapper.flush` reproduces the same failure independently. The traced fd is O_RDONLY, fstat identifies a regular procfs inode, fstatfs type is 0x9fa0, and fsync returns EINVAL. The original seal correctly refuses that mistaken persistent destination. The negative control adds diagnostic printing only in a private copy of the old header; its policy is unchanged.

The correction is at the native caller. It accepts only exact built-in TextIOWrapper/BufferedReader/FileIO chains with no overridden instance callbacks, the real FileIO C writable flag false, current descriptor access O_RDONLY, matching native fileno and stable fstat identity/flags, and no outstanding dirty buffer. Only that flush/close operation uses the existing nonpersistent sentinel. No filesystem prefix, procfs type or fsync failure is exempted. BeginProtectedOperation, SyncProtectedPath and SealEssentialWrites remain unchanged.

Nine new cases cover read-only procfs close/flush/late close, regular-file input, injected real user-file fsync failure, a genuine procfs write, an overridden close callback and both directions of descriptor retargeting. Four existing write/buffer/race controls also pass locally. Full CI retains the original 52 native cases and all 308 Android cases. TEST3 remains subject to internal acceptance and new physical Fold approval; no lock.
