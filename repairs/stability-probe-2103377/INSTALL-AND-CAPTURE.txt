INFINITY STABILITY EVIDENCE RC1 — DIAGNOSTIC TEST ONLY

This candidate collects the missing evidence needed for a verified repair.
It does not claim to fix shutdown, the ANR or loading performance. Do not lock it.
There is no direct Fold/ADB connection in this environment.

Preserved parent: Infinity 2103377 Rails Hold RC02, skin 1.0.5.223, helper 0.2.5.
The APK keeps the same package, versionCode and permanent certificate for in-place
installation/rollback. Only its native library and diagnostic version label change.
Skin .223 stays installed. Helper .026 preserves Mocha, all card actions, defaults,
storage format and saved rail preferences; it adds Stability Evidence to its root
program menu and bounded listing timings. No provider is disabled or modified.
All final save, transaction and termination gates remain in force.

INSTALL
1. Retain your exact locked RC02 APK and helper .025 ZIP.
2. Close Infinity normally. Install the test APK over the existing app.
3. Install helper .026 through Install from ZIP, then reopen Infinity normally.
Never uninstall, clear data or reset settings. No skin repatching is required.

ONE TARGETED CAPTURE
1. Open Infinity Add-on Rails from Program Add-ons. Select Stability Evidence,
   then Arm five-minute stability capture. Return to Home.
2. Visit Movies, then TV Shows. Allow each rail and Continue Watching panel to
   appear. Try normal scrolling and the previously troublesome action once.
3. With providers fully loaded, request Normal Close once. If it reports that
   saving is blocked, do not repeatedly force termination. Export when available;
   an unfinished checkpoint must retain its normal protections.
4. Reopen normally if Close succeeds. Open the helper's Stability Evidence menu
   and select Export current/previous evidence. Choose a writable folder.
5. Send the generated Infinity-Stability-YYYYMMDD-HHMMSS.zip and the normal
   chooser Export Diagnostics ZIP from the same attempt. State whether the app
   had just opened or was fully loaded, which action stalled, and approximate time.

The native capture uses the existing responsiveness watchdog, with no new
service or polling thread. Lock bookkeeping is bounded. Captures stop after
their time/count/size limits. Only Umbrella's service interpreter and its child
threads receive the diagnostic call profiler. That profiler can affect timing;
this package is evidence gathering, not a speed acceptance build. Existing
profilers present at service startup are left alone. No arguments, SQL text,
credentials, settings contents or Python local variables are captured.

Exports contain native lock owners/waiters, operation locations, observed render
transitions, Rails/Resume timing rows, installed code hashes and selected public
Umbrella code, plus existing checkpoint receipts. Missing evidence is reported
as unavailable. Native probe logs retain the current and previous process only.
Those probe-owned logs rotate; user settings, rail preferences and databases do
not. Keep exported captures if you need a longer history.

VERIFICATION LIMIT
Host OS mutex and real CPython checks, preserved regression suites, full matched
native compilation, package preservation and signing gates must pass before
delivery. The real Kodi smoke uses a disposable Home/stock dialog fixture. It
does not inject Android touch, validate Infinity theme rendering or prove Fold
shutdown. No before/after improvement timing is claimed by this candidate.
The complete shutdown/ANR/playback/Fold/long-session acceptance matrix remains
pending the evidence-supported correction and physical testing.
