## Demonstrated Infinity-owned defect and targeted correction

Signed Main queues its initial URI with a5000ms delay. Resumed `onNewIntent` can dispatch a newer URI immediately. Main$3 checks destruction, the existing exit plan and pause state, but never checks whether its old request was superseded. The exact baseline callback reproduced native-endpoint dispatch order **B then old A**. A second baseline reproduction shows multiple paused requests all dispatch on resume. This is a concrete external-file ordering defect; its causal connection to the user's particular Stop freeze or Loading overlay is **not established**.

`InfinityExternalVideoIntents` assigns a per-Main request ticket at acceptance and checks it before the original JNI handoff. Only the latest pending local video reaches JNI; a request already dispatched cannot be dispatched a second time through duplicate callbacks. Explicitly reopening the same URI creates a fresh request and remains allowed. The helper uses weak Activity ownership and adds no worker, timer, polling, persistence or engine restart. Internal/private tickets are removed before native delivery; action, MIME, URI, flags, ClipData contents, categories and caller extras remain intact.

The correction deliberately applies only to ACTION_VIEW requests with `file://` or `content://` URIs and a supplied `video/` MIME type. Other schemes, missing MIME, audio, ACTION_GET_CONTENT, launcher and legacy unstamped routes retain original dispatch. The actual MiXplorer intent MIME/URI has not been captured, so applicability to the reported physical sequence remains unverified.

The three modified methods are Main.onCreate (only its cold intent copy), Main.onNewIntent (acceptance plus its existing immediate handoff) and Main$3.run (its existing native handoff). Original5000/500ms delays, all original pause/destruction/exit admission checks, and onResume/onPause/onStop/onDestroy remain unchanged. There is no generic dialog close, fabricated readiness or Back/Stop interception. Already-delivered native playback requests and native asynchronous results remain Kodi-owned.

The test-only compiled DEX preserves original fields/annotations, **576 original Infinity classes** and every other original method. Only the two original classes above and two new policy/state classes differ. No deployed component ZIP or APK was repacked. [Exact method and source proof](evidence/OWNER-PRESERVATION.json), [unchanged Main methods](evidence/UNCHANGED-MAIN-METHODS.json) and [protected input bindings](evidence/BASELINE-BINDING.json) are retained.
