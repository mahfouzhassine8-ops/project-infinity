# Physical-device acceptance — 2103203

These checks are not completed by host or Android/Robolectric tests. Record model, Android/One UI version, installed build, call type and output route. Use channel aliases; do not export credentials, contact details or full stream URLs. Mark each item PASS / FAIL / NOT TESTED.

1. Install the candidate as an update over locked 2103202 without clearing data. Confirm sources, favorites, recents, themes, subtitle preferences, channel overrides and recordings persist. If Android rejects an update or downgrade, stop rather than uninstalling or clearing data.
2. Enter PiP while playing live, rewound live and VOD. Tap the PiP window and use Play/Pause repeatedly. Verify the visible icon matches intent, pause stops both audio and motion, Play resumes the same owner/position, and no duplicate session starts. Try after buffering, an error, a channel switch and an app-icon return. Check SystemUI behavior, not only in-app state.
3. Repeat PiP with 2, 3 and 4 Multi-View tiles, a non-first audio owner and another tile paused. Pause/resume the PiP owner and return by expansion, Recents and app icon. Preserve layout, order, audio owner and other tiles' pause intent. Dismiss PiP and reopen; do not autoplay removed or stale tiles. Repeat ten cycles and check there is no hidden audio.
4. With another person's consent, test an incoming cellular call during Cobra playback. For continuity while the call screen backgrounds Cobra, first enable the existing Channel playback PiP or background-playback option. Record separately whether video continues, whether Cobra audio is audible and whether call audio remains usable. Test explicit Play during the call. If the OS refuses focus or mutes playback, record that limitation; a moving video or volume value is not audible-call verification. Repeat with both options disabled and verify the existing background-pause choice is respected; this candidate does not silently override it.
5. Test an outgoing call, then intentionally start Cobra playback while that call is already active. Repeat using speaker, earpiece and supported wired/Bluetooth routes. Test a VoIP call separately. Do not assume one call type or route proves the others. Do not change audio routing automatically or expose call audio to an unintended speaker.
6. End the call and verify recovery without duplicate playback. Pause Cobra manually during the call, end it and confirm it stays paused. Test another media app, navigation prompt and headphone removal; unrelated focus loss and user pause must remain respected. Repeat with foreground, PiP and already-enabled background playback.
7. On a stream known to carry usable captions, choose English, Off and English again by glyph, label and row edge. Confirm actual captions, immediate Off and no stale cues; repeat twenty times. Reopen the menu. On a stream with no detected track, ensure Off is explained clearly and preferred English does not imply active captions. Allow for late track discovery and test an unsupported track if available.
8. Check inherited subtitle size/adaptation, light/dark/OLED/system themes, D-pad focus, scrubber holding/dragging, live shading, rewind/pause/resume/live return and source management. Every display mode remains individually required; Fold Adaptive must fit the whole frame proportionally within the real window. Bars can be correct when source and window shapes differ.
9. Rotate, fold/unfold, resize split-screen and return from PiP with the controls or subtitle sheet open. No stale geometry, clipping, duplicate overlays or surface loss. Repeat navigation/background/foreground cycles and one long playback session on known-good and problem channels without changing provider/network settings.
10. Compare exported diagnostics against the actual owner, focus state, pause intent and visible subtitle selection. Confirm no credentials or sensitive call/provider information is included.

Any playback, call-recovery, PiP, Multi-View, timeshift or Fold regression blocks acceptance even if both signed CI builds pass. Audible call mixing and physical PiP control rendering remain unverified until the relevant device rows above pass.
