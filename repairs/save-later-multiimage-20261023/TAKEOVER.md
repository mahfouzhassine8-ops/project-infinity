The physical rejection of run 39914382723 supersedes its host-only reports.

## Navigation correction

The rejected resolver replaced every Save for Later target with `open-later`.
It treated valid original providers outside its discovery recipes as unavailable
and ran preliminary directory requests before normal navigation. The replacement
restores `_target`, `_list_item`, listing and playback functions exactly to RC8.
Only a `saved-fallback` handler is added to the controller dispatcher.

Native result observation is limited to Infinity Save for Later clicks. The
complete original folder-update and plugin-resolution bodies remain verbatim,
including their returns and error behavior. A failed result can publish a
short-lived correlation ticket; successful navigation never calls the resolver.
Cancellation and Close do not offer new work. No writer or durability receipt
is created by navigation correlation.

Recovery reads the original saved record and verifies the key, typed identity,
original route hash and current failed attempt. Switching providers requires
explicit selection. ID-addressed, installed-source-verified show APIs can open
directly; APIs needing a provider result use the existing bounded consumer and
require matching typed IDs. No cache, database or provider source is repaired by
this path. Original provider preference and saved membership remain unchanged.

The revised observer follows actual FileDirectoryFactory dispatch. Merely

playlist and other unreviewed handlers reject before their first call, including

The failed Fold archive retains `completed_write_failed:multiimage-enumeration`
but not that job's full resource/failure-detail receipt. The later 2.53-second

## Cobra preservation audit

The activity described as a guard concerns these Infinity repair inputs:

- `native_contract.py`: generates the multi-image job declarations and observer.
- `multiimage_methods.inc`: generates the Infinity skin admission condition.
- `test_native.py`: contains a disposable other-skin negative control.

Generated targets for this guard are `xbmc/guilib/GUIMultiImage.cpp` and `.h`
inside the reconstructed Infinity engine source. It is a runtime condition,
not solely a build check. Outside Infinity it delegates to the pre-existing
CJob contract and does not create the new observation. No Cobra Java source,
resources, signing inputs or build configuration is edited. All 9,404 original
native-source inputs are hash-verified before the 13-file overlay is applied;
the six Cobra/InfinityLive source files are outside that overlay.

An independent audit of the *rejected* APK found one Cobra instruction widened
from `const-string` to `const-string/jumbo` for the unchanged `xmltv.php` value.
Two shared-library classes had the same encoding change. The older DEX guard
normalized these away. That is insufficient for this preservation requirement.
The new packager encodes new hashes as character payloads, reuses an existing
method-name string and requires the original string pool to remain identical.
Every other class must have byte-identical canonical disassembly, with no opcode
normalization. The packager must fail before producing an APK if this gate fails.
This correction is not marked passed until an actual DEX is produced and checked.

The existing rejected APK has 19 changed ZIP members relative to RC8: eleven
Infinity component members, two Infinity component manifests, primary DEX,
Infinity engine and its crash build binding, plus three signature members.
AndroidManifest, classes2 and all other members are identical. This is an audit
of the existing rejected artifact, not an inventory or approval of a new APK.
