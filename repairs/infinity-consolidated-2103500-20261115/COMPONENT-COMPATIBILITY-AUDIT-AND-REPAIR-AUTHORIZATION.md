## Required investigation-to-repair loop

1. **Identify active runtime, not merely installed inventory:** On the actual 502 process, compare Kodi-resolved `xbmcaddon.Addon(id).getAddonInfo('path')`, version and enabled state, loaded Python module `__file__`, active skin root and source hashes with packaged APK bytes. Distinguish previous installed500 evidence from current signed502 state. Avoid user-sensitive paths/URLs in published receipts.
2. **Match symptom to cause:** Capture one actual request at the native `RunScript` → `ExecuteAsync` admission boundary, interpreter/GIL/observer entry, selected add-on module-contract import/dispatch, menu selection and result. When a prior failed checkpoint is suspected, match **the same PID and process generation**; separate a stale admission gate from a fresh-process startup failure. Use retained evidence where possible, not repeated user testing.
3. **Correct only proven incompatibility:** If a stale service/wrapper executes, repair its verified first-party runtime binding or release-compatible version selection using existing trusted module conventions. If correct code executes but rejects valid typed identities, repair the single universal result-to-context handoff. If the component is intentionally newer/different and functional, **do not change it**.
4. **Focused verification:** For each correction, run before/after reproduction and host/Android checks using exact source, verify metadata and identity preservation, and have Astra independently review the source + packaged delta. No bypass of identity checks, startup admission, SQLite/write protection, provider authorization or original signing controls.
5. **Integrate forward:** After proven fixes pass, prepare **one** 502-derived original-signed successor QA APK and appropriate forward recovery, with new release-registry versions; preserve 502 and 503 signed artifacts, all settings, history, Cobra and working Cast. No claim of physical Fold acceptance before the owner tests.
